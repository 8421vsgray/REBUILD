# REBUILD 补充约束：算法边界、数值正确性与实验可信性

以下要求是 REBUILD 总任务的规范性补充，优先级高于代码风格、运行速度和实验指标。它们必须与 `REBUILD_TASK_PROMPT.md`、`REBUILD_NAMING_REFACTOR_PROMPT.md` 以及 `REBUILD_LEGACY_ALGORITHM_REMOVAL_PROMPT.md` 一起执行。

## 1. 禁止未经授权的算法变更

REBUILD 的目标是按 STRIDE 的既定数学机制重建模型。不得擅自增加新损失函数或正则项、新置信度门控、新 Sinkhorn/Partial OT 分支、新 GMM 或聚类引导机制、新视图融合策略、基于测试集 ACC 的参数自适应、未经要求的先验锁定、动量融合或其他历史实验性机制。

如果实现过程中认为某项数学设计不合理，应提交分析报告，而不是自行修改算法。

## 2. 明确区分两种 Warmup

训练算法严格只有两个阶段：`Diagonal Warmup` 和 `GW Structural Supervision`。

学习率调度器的 Warmup 是独立的优化器机制。删除 CorreGen 第三阶段时，不得错误删除学习率 Warmup，也不得把 `warmup_epochs` 与 `diagonal_epochs` 混为一谈。两个参数必须分别配置和记录。

## 3. GW 迭代必须保留完整数学语义

每次 GW 扩散至少记录：输入关系矩阵的形状和数值范围、初始耦合、梯度范数、更新步长、投影前候选矩阵、投影后边缘残差、投影成功/失败状态和最终非对角质量。

正式训练不必长期保存完整矩阵，但调试模式必须能够导出指定 Batch 的数据供独立复核。

投影失败时，不允许继续使用不合格耦合进行监督。应保留上一可行耦合、终止本次扩散并记录失败；具体策略必须通过测试确认。两个跨视图方向的统计必须分别保存，不能被后一次调用覆盖。

## 4. DROT 不得静默失败

DROT 只有在实际通过精度检查后才能标记成功。至少检查非负性、行边缘残差、列边缘残差、总质量、非有限数值和小规模问题的最优性误差。

状态必须明确区分：

- `success`
- `invalid_input`
- `infeasible_output`
- `numerical_failure`
- `not_verified`

不得因输出矩阵存在就判定成功。DROT 失败时不得私自使用 Newton 或 Sinkhorn 替代而继续宣称结果来自 DROT；任何备用求解都必须显式配置、独立记录。

## 5. DROT 精度标准由 REBUILD 控制

DROT 的 `eps` 是求解器内部容差，不等于 STRIDE 的相对边缘容差。REBUILD 必须自行计算：

\[
r_{row}=\frac{\left\|T\mathbf 1-a\right\|_\infty}{1/B},\qquad
r_{col}=\frac{\left\|T^\top\mathbf 1-b\right\|_\infty}{1/B}.
\]

由统一精度协议决定是否接纳结果，不得直接把 Newton 的 `relative_tol` 传给 DROT 的 `eps`。必须覆盖 Cost 归一化、`r_weight` 缩放、大 Batch、近对角输入和极端小数值范围。

例如 `B=1024` 时目标行和约为 `0.000977`。绝对残差 `1e-4` 对应约 `10.24%` 的相对残差；相对残差 `1e-3` 要求绝对误差约不超过 `9.77e-7`。这只是换算关系，不能代替实际测试。

## 6. 严格限定真实标签的使用范围

真实类别标签只能用于数据协议验证、聚类性能评估和必要的离线诊断，不得参与编码器训练、GW 伪标签生成、投影求解、超参数自适应或跨视图样本匹配。

噪声置换索引可用于检查人工噪声构造，但不得作为训练时的真实对应监督。CAR 是类别层面的匹配一致率，不等价于真实样本身份恢复率。

## 7. 数据协议必须独立验证

YAML 必须明确规定数据集、两个视图的选择和顺序、固定主视图、被扰乱视图、噪声率、随机种子、标准化方式和模型输入维度。

每个数据集都要验证实际特征维度与配置一致，区分配置噪声率、参与置换的样本比例和置换后实际改变身份的比例。数据加载代码不得自动交换视图来适配模型；方法比较必须使用可解释、可核查的噪声协议。

## 8. 不允许静默跳过训练样本

审查 CorreGen 对尾部小 Batch 的处理逻辑。不得未经声明就跳过不足半个 Batch 的样本。如果算法确实不能处理过小 Batch，应在配置中明确 `drop_last` 或其他策略，并记录实际训练样本覆盖情况。

## 9. 保持评估过程无状态

评估不得更新模型权重或 EMA 状态、修改训练数据或配置、意外改变训练所需的随机数状态、使用真实标签构造测试特征或根据测试 ACC 选择有利的 Batch 分组。

评估应使用独立随机数生成器和固定协议。`eval_batch_size` 默认使用 YAML 中的 `batch_size`，但允许明确配置；不同 Batch Size 的结果必须如实记录。

## 10. 禁止结果驱动的隐式调参

正式实验必须固定代码 Commit、训练配置、评估配置、数据与噪声协议、随机种子集合和 checkpoint 选择规则。

不得根据测试集 ACC 自动选择最优种子、评估 Batch Size 或 GW 步数后，将其作为无偏最终结果。必须保留每个种子的原始指标、均值和标准差。

## 11. Git 与运行环境必须隔离

正式训练阶段不允许修改正在使用的源码。建议在固定 Commit 的 Git Worktree 或隔离环境中运行训练。日志、checkpoint、数据和缓存必须位于独立实验目录，运行过程不得产生未记录的源码变更。

不得使用 `git reset --hard`、`git clean -fdx` 等破坏性命令清理用户已有工作，除非已明确限定安全范围并确认不会丢失文件。

## 12. 严格禁止虚假验收

报告必须区分：已通过独立数值测试、仅通过基本运行测试、编译成功但数值未验证、测试失败，以及因环境或数据缺失而未执行。

禁止用“应该正确”“理论上没问题”“测试基本通过”作为正式验收结论。不能为使测试通过而放宽容差却不记录，也不能为提高 ACC 而降低投影精度后声称算法未改变。

## 13. 最终必须提供可复核的验收报告

生成 `docs/REBUILD_VERIFICATION_REPORT.md`，至少包括：

1. CorreGen 基线 Commit。
2. REBUILD 当前 Commit。
3. DROT 上游 Commit。
4. 删除的 CorreGen 遗留机制。
5. 保留的原始模块。
6. STRIDE 新增的算法机制。
7. GW 梯度测试结果。
8. DROT 数值正确性报告。
9. CUDA 编译与运行状态。
10. 实际训练的端到端验证结果。
11. 评估协议与样本覆盖验证。
12. 已知限制和未解决问题。

每项结论都必须有实际测试、代码或日志证据。

## 需求冻结

不要把重建过程变成重新调参。先保留 CorreGen 的编码器、优化器和原始最大似然损失，只移除不需要的算法，再引入 STRIDE 的 GW+DROT。等 REBUILD 跑通且数值验证合格后，再讨论 ACC 是否达到历史 STRIDE 水平。

在上述约束之外，不再自行增加新模块、新损失、新门控或实验性机制。最终完成标准是数学行为正确、实验条件可追溯、异常能够暴露、结果能够独立复核，而不是单纯代码能运行或 ACC 更高。
